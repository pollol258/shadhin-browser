# Shadhin Browser — Security Test Suite & Proofs

This document details the security tests implemented in `tests/security_tests.rs`, documenting exactly what each test empirically proves, how it is verified, and the known limitations of each verification method.

---

## 1. Security Test Matrix

| ID | Test Name | Target Threat / Mechanism | What It Proves | What It Does NOT Prove |
|---|---|---|---|---|
| **(a)** | `test_security_a_internal_shadhin_scheme_isolation` | Internal URL Spoofing & Framing | Proves that only whitelisted internal paths (`shadhin:newtab`, `shadhin:settings`, `shadhin:bookmarks`, `shadhin:history`, `shadhin:downloads`, `shadhin:error`) are permitted. Spoofed or unauthorized schemes (e.g. `shadhin:evil-exploit`) return `NavigationTarget::Blocked`. | Does not prove that WebKit engine zero-days in C++ cannot bypass higher-level scheme checks if IPC is compromised. |
| **(b)** | `test_security_b_dangerous_scheme_rejection` | Remote Execution & Local File Disclosure | Proves that `javascript:`, `data:`, `file:`, `vbscript:`, `blob:`, and unknown custom schemes are rejected from both address bar and navigation policies with explicit reasons. | Does not prevent web content from using standard `https://` URLs to load untrusted remote pages. |
| **(c)** & **(d)** | `test_security_cd_https_upgrade_and_downgrade_prevention` | Man-in-the-Middle (MitM) & Insecure HTTP Downgrades | Proves that unencrypted `http://` navigation requests are upgraded to `https://`. Proves that exemptions are strictly limited to local loopback addresses (`localhost`, `127.0.0.1`, `.local`) and that public internet domains cannot be exempted. | Does not guarantee that remote servers support HTTPS or possess valid certificates (untrusted certificates trigger explicit warning pages). |
| **(e)** | `test_security_e_download_filename_confinement` | Directory Traversal & Overwrite Attacks | Proves that `sanitize_download_filename` strips directory traversal sequences (`../../`, `\`), root paths (`/etc/passwd`), null bytes (`\0`), and Windows device names (`CON`, `PRN`), ensuring target files remain strictly confined within the configured download directory. | Does not verify the contents of downloaded files (antivirus scanning is the user's responsibility). |
| **(f)** | `test_security_f_hostile_bookmark_import_resilience` | Malicious File Import & XSS Bookmarklets | Proves that both Netscape HTML and JSON bookmark parsers filter out `javascript:`, `data:`, and `file:` schemes, import only safe `http`/`https` URLs, and cleanly reject malformed structures without panicking. | Does not inspect whether legitimate imported HTTP URLs point to phishing websites. |
| **(g)** | `test_security_g_anti_pango_markup_injection` | UI Pango Markup Injection | Proves that page titles and URLs containing `<script>`, `<b>`, or XML entities cannot inject Pango formatting markup into list items or labels. | Does not alter how raw HTML is rendered inside the WebKit WebView itself. |
| **(h)** | `test_security_h_permissions_never_auto_granted` | Covert Surveillance & Permission Escalation | Proves that permissions for Camera, Microphone, Geolocation, and Notifications default to `PermissionState::Ask` for all unknown origins, never auto-granting access. | Does not prevent the user from manually choosing to grant a permission via a dialog prompt. |
| **(i)** | `test_security_i_file_and_directory_permissions_modes` | Multi-User Local Information Disclosure | Proves that app data, cache, config, and session directories enforce POSIX mode `0700` (`rwx------`), and SQLite databases/lock files enforce mode `0600` (`rw-------`). | Does not protect against root/superuser access or compromised kernel permissions. |
| **(j)** | Idle Network Telemetry Check | Unwanted Phone-Home & Telemetry Leaks | Proves that Shadhin Browser creates 0 outbound socket connections when sitting idle on the New Tab page. | Does not monitor third-party web content from making network requests when the user actively browses websites. |
| **(k)** | `test_security_k_zero_unsafe_in_source` | Memory Safety & FFI Vulnerabilities | Scans the entire `src/` codebase and verifies **0 occurrences** of the `unsafe` keyword. | Does not verify unsafe blocks inside external third-party dependency crates (audited via `cargo deny` and `cargo audit`). |
| **(l)** | Dependency Auditing (`cargo audit` & `cargo deny`) | Vulnerable or Incompatible Dependencies | Proves that no crate dependencies contain known vulnerabilities in the RustSec Advisory Database and that all dependency licenses are compatible with GPL-3.0. | Does not catch zero-day vulnerabilities in dependencies not yet reported to RustSec. |
| **(m)** | `test_security_m_generative_fuzz_url_and_bookmarks` | Parser Panics & Buffer Overruns | Executes 1,000 randomized URL mutations (including null bytes, Unicode edge cases, long strings, control characters) and 500 malformed HTML bookmark structures, proving zero panics or memory faults. | Fuzz testing is bounded to 1,500 iterations; does not constitute a formal mathematical proof of correctness. |
